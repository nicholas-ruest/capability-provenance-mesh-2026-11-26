## Recommended product hypothesis

### Capability Admission & Replay Control Plane

An operator submits an agent capability bundle (skill, MCP server, Agent Card, plugin, tool manifest, or model adapter). The product binds acquisition origin, scans code and dependency surfaces, constructs an evidence graph, checks authority and reversibility, executes the candidate in an isolated memory branch, signs the admitted bundle, and exposes an auditable allow/deny decision. A denied candidate must produce zero downstream dispatches and zero parent-memory mutations. Every decision is replayable after refresh and backend restart.

The frontier mechanism is **evidence-closed adaptive admission**: Autogenous typed mutations and hard fitness gates determine whether a capability can be promoted; RuGraph preserves uncertainty, sensitivity audits, and receipt replay; Agenticow provides copy-on-write quarantine and rollback. The hypothesis is that this combination catches cross-surface attacks missed by a static scanner without materially reducing benign admission or making denial side effects possible.

## Product-shape and experiment fit

The hypothesis supports at least 22 non-ceremonial Rust product crates: `admission-domain`, `bundle-model`, `origin-proof`, `manifest-parser`, `dependency-surface`, `scan-adapter`, `sarif-ingest`, `authority-lattice`, `reversibility`, `evidence-graph`, `sensitivity-audit`, `receipt-replay`, `quarantine-memory`, `branch-diff`, `promotion-envelope`, `signature-verifier`, `watermark-provenance`, `gateway-policy`, `dispatch-ledger`, `event-stream`, `audit-store`, and `api-service`. A React console can expose candidate inventory, evidence graph, denied effects, replay comparison, and durable audit retrieval.

Three required journeys fit naturally:

1. **Primary:** submit a benign capability → bind origin → scan → graph → quarantine execution → sign → admit → render evidence.
2. **Denial/recovery:** submit a candidate with a hidden dependency and authority expansion → SkillSpector and Autogenous deny → prove zero gateway dispatch and unchanged parent branch → fix and resubmit successfully.
3. **Durable retrieval:** save an admitted bundle and audit → refresh → restart Rust backend and event/storage components → retrieve and replay the exact decision.

Benchmark arms:

- A: static manifest allowlist and SkillSpector only.
- B: SkillSpector + ContextForge gateway.
- C: full evidence-closed mechanism (B + Autogenous + RuGraph + Agenticow + Cosign; Ruflo orchestration).

Pre-registered success criteria: all malicious fixtures denied; zero forbidden downstream calls; zero parent-memory change on denial; 100% receipt replay parity; at least 95% benign admission; denial-to-recovery journey succeeds; restart retrieval succeeds; p95 orchestration overhead no more than 35% over B. Ablate origin binding, authority lattice, sensitivity audit, branch isolation, and signature verification independently. Reject the mechanism if any security criterion fails or if benign acceptance drops below the threshold.
