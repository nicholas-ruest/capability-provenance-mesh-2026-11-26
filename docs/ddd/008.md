# DDD-008: Receipts and audit

## Model and purpose
ExecutionReceipt proves an operation while AuditEvent records a command and outcome.

## Ubiquitous language and invariants
receipts are immutable; audit is append-only and hash-linked. Commands carry explicit identity and expected prior state. Queries return source-bound projections. Adapter failure cannot masquerade as domain approval.

## Ownership and verification
- Production path: `crates/cpm-receipts/src/lib.rs`
- Behavior or failure test: `crates/cpm-audit/tests/hash_chain.rs`
- Orchestration boundary: `crates/cpm-application/src/lib.rs`
- API boundary: `crates/cpm-service/src/api/v1.rs`

## Acceptance evidence
exact argv and restart establish causality. Composition schema 2 maps this record reciprocally to production callers and tests; external evidence is exact-SHA bound.
