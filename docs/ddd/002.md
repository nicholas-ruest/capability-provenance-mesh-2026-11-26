# DDD-002: Candidate aggregate

## Purpose and scope
A Candidate is normalized bytes plus digest, parsed declaration, and lineage. Labels are descriptive, not identity.

## State constraints
Candidate creation fails before upstream work on empty bytes or malformed manifest. Parent relationships never change the digest.

## Realization
| Concern | Existing path |
|---|---|
| aggregate behavior | [crates/cpm-artifact-intake/src/lib.rs](../../crates/cpm-artifact-intake/src/lib.rs) |
| integration or failure proof | [crates/cpm-manifest/src/lib.rs](../../crates/cpm-manifest/src/lib.rs) |

## Completion criterion
Inline failures and the intake API show one digest across later records.
