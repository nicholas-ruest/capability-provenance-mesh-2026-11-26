# ADR-023: Frontier evaluation measures component decision deltas

**Status:** Accepted

## Context

The earlier experiment compared a declaration-only baseline with the complete application and then called seven missing-receipt failures “mechanism ablations.” Those failures are valuable integration tests, but they cannot support the research claim that graph completeness, authority attenuation, lineage enforcement, and upstream consensus each contribute independently. A benchmark that only times a successful request or removes an upstream receipt confounds policy semantics with dependency availability. It can pass even if three of the four claimed checks have no effect.

## Decision

Keep the 40-decision end-to-end production benchmark and the seven leave-one-upstream-out checks. Add a separate frozen 25-case, pre-persistence component-isolation corpus built from the production `EffectGraph`, `CapabilitySet`, and `Lineage` types and the canonical seven-ingredient set. Five cases are safe. Each of four unsafe classes has five deterministic repetitions and invalidates exactly one mechanism: a missing effect path, an observed capability outside the declared set, an artifact digest mismatch, or six rather than seven canonical receipts.

`MechanismConfig` makes the four checks explicit. The component-free baseline, full configuration, and four configurations with exactly one check disabled run on identical cases. Each report includes safe acceptance, unsafe admission/blocking, per-fault unsafe admissions, balanced quality in basis points, and forbidden active writes. Experimental unsafe decisions are never persisted. Production denial safety remains a distinct `Application::submit` plus retrieval assertion.

The evaluator is equivalent to this policy skeleton:

```text
deny if enabled(graph) and not all observed effects are reachable from artifact
deny if enabled(authority) and observed is not a subset of declared
deny if enabled(lineage) and artifact bytes do not match the bound digest
deny if enabled(consensus) and canonical receipt count is not seven
otherwise admit, but persist only outside the experiment
```

## Alternatives considered

- **Treat missing upstreams as all ablations.** Rejected because it measures evidence availability, not the four internal mechanisms.
- **Add booleans to the production service.** Rejected because runtime weakening switches create an unnecessary security surface. The experiment composes the same typed domain APIs before persistence instead.
- **Use four fixtures where several checks fail.** Rejected because the first denial would mask the contribution of later checks.
- **Report latency only.** Rejected because speed cannot establish admission quality or absence of forbidden writes.

## Consequences

The claim is now falsifiable: full composition must score 10,000 balanced-quality basis points; the component-free baseline scores 5,000; and each single-component ablation must expose exactly five target faults and score 8,750. The design adds a small deterministic corpus and duplicates orchestration of production domain APIs in an experiment-only module. That duplication is intentional and bounded: it makes component toggles testable without shipping bypasses. It does not establish population-level effectiveness, independence under arbitrary correlated faults, or external upstream correctness.

Per-candidate complexity is `O(K(V+E) + D + O + B + U)`, where `K` is observed effects, `V/E` are graph nodes/edges, `D/O` are capability-set sizes, `B` is artifact bytes, and `U` is canonical upstreams. Memory is linear in the same bounded structures.
