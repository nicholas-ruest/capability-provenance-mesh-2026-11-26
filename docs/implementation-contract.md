# Implementation contract

## Build order

1. Preserve canonical gate bytes from the first commit.
2. Complete readiness probes and schema-1 selection before any remote repository.
3. Implement the first running slice before bulk crate/doc expansion.
4. Expand three complete workflows.
5. Complete every meaningful crate and substantive ADR/DDD alongside behavior.
6. Run the full exact-source evidence collector and independent semantic review.

## First running slice

`upload fixture -> typed client -> versioned API -> registered middleware -> intake/lineage -> RVM inspect -> Rune verify -> Wasmtime trial -> LatentMesh observation -> WorldGraph closure -> APx eligibility -> Cedar decision -> OpenDAL write/read -> rendered result`.

The slice must execute before the planned workspace grows to twenty crates. A green slice is not completion.

## Meaningful crate rule

A counted crate owns useful behavior, a typed public API, a production dependency/caller edge, behavior and failure tests, acceptance criteria, and reciprocal ADR/DDD mappings. Tiny wrappers, aliases, one-function validators, development-only tools, disconnected packages, and duplicate domain functions do not count.

## Upstream rule

Every credited upstream has a canonical repository, immutable revision, verified OSS license, useful responsibility, installed/linked or pinned-service binding, real application call site, integration and failure test, and runtime evidence. An adapter that never invokes upstream code does not count.

## API/middleware rule

OpenAPI is versioned and generates/checks the TypeScript client. Middleware controls are explicitly registered and tested in the documented order. Denial must prove the forbidden registry activation/current-pointer side effect did not occur.

## Durability rule

Durable retrieval must survive browser refresh and Rust backend restart. Rebuilding from append-only events and immutable objects is the authoritative path. In-memory doubles remain test-only.

## Completion rule

The canonical full-product wrapper runs all ten suites and the verifier against a clean immutable candidate with external schema-v2 evidence. Structural passes never replace semantic inspection.
