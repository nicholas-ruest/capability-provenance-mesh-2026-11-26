# DDD-002: Candidate intake and lineage

## Model and purpose
Candidate is immutable bytes, source pin, license, manifest, and quarantine location; filename and URL are attributes.

## Ubiquitous language and invariants
same bytes re-intake idempotently; changed bytes create a new identity. Commands carry explicit identity and expected prior state. Queries return source-bound projections. Adapter failure cannot masquerade as domain approval.

## Ownership and verification
- Production path: `crates/cpm-intake/src/lib.rs`
- Behavior or failure test: `crates/cpm-lineage/tests/revision_mismatch.rs`
- Orchestration boundary: `crates/cpm-application/src/lib.rs`
- API boundary: `crates/cpm-service/src/api/v1.rs`

## Acceptance evidence
receipt binds bytes, pin, and license. Composition schema 2 maps this record reciprocally to production callers and tests; external evidence is exact-SHA bound.
