# DDD-011: Application orchestration

## Model and purpose
application owns intake, inspect, trial, decide, remediate, promote, rollback, and query boundaries.

## Ubiquitous language and invariants
ports are injected by service; denial never invokes dispatch or promotion. Commands carry explicit identity and expected prior state. Queries return source-bound projections. Adapter failure cannot masquerade as domain approval.

## Ownership and verification
- Production path: `crates/cpm-application/src/lib.rs`
- Behavior or failure test: `crates/cpm-application/tests/no_effect.rs`
- Orchestration boundary: `crates/cpm-application/src/lib.rs`
- API boundary: `crates/cpm-service/src/api/v1.rs`

## Acceptance evidence
composition and traces prove real callers. Composition schema 2 maps this record reciprocally to production callers and tests; external evidence is exact-SHA bound.
