# DDD-006: Admission governance

## Model and purpose
AdmissionCase aggregates candidate, effective grant, complete evidence, and operator authority.

## Ubiquitous language and invariants
only governance emits Approval; promotion is separate; reevaluation never rewrites history. Commands carry explicit identity and expected prior state. Queries return source-bound projections. Adapter failure cannot masquerade as domain approval.

## Ownership and verification
- Production path: `crates/cpm-policy/src/lib.rs`
- Behavior or failure test: `crates/cpm-policy/tests/decision_table.rs`
- Orchestration boundary: `crates/cpm-application/src/lib.rs`
- API boundary: `crates/cpm-service/src/api/v1.rs`

## Acceptance evidence
failure matrix proves guarded transitions. Composition schema 2 maps this record reciprocally to production callers and tests; external evidence is exact-SHA bound.
