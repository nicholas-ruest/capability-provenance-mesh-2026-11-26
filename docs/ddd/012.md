# DDD-012: Operator API and browser

## Model and purpose
api/v1 exposes workbench, graph, trials, decisions, remediation, registry, and audit through generated client.

## Ubiquitous language and invariants
UI renders loading, empty, error, denied, incomplete, approved, and restarted states accessibly. Commands carry explicit identity and expected prior state. Queries return source-bound projections. Adapter failure cannot masquerade as domain approval.

## Ownership and verification
- Production path: `crates/cpm-service/src/api/v1.rs`
- Behavior or failure test: `tests/browser/journeys.spec.ts`
- Orchestration boundary: `crates/cpm-application/src/lib.rs`
- API boundary: `crates/cpm-service/src/api/v1.rs`

## Acceptance evidence
three desktop/mobile journeys bind UI to storage. Composition schema 2 maps this record reciprocally to production callers and tests; external evidence is exact-SHA bound.
