# DDD-011: Application orchestration

## Purpose and scope
Submit is the product transaction: create candidate, gather seven upstream results, build evidence, decide, persist, then conditionally activate.

## State constraints
A failure stops activation but retains a decision/audit trail. Queries read projections without rerunning upstreams.

## Realization
| Concern | Existing path |
|---|---|
| aggregate behavior | [crates/cpm-application/src/lib.rs](../../crates/cpm-application/src/lib.rs) |
| integration or failure proof | [crates/cpm-store/src/lib.rs](../../crates/cpm-store/src/lib.rs) |

## Completion criterion
Application tests and restart journey prove call order and idempotent retrieval.
